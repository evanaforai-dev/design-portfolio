lipi

a figma plugin that pressure-tests a screen against localized copy, then points at the component causing the break.

code ↗

localization usually turns up after the layout is finished, as a developer's bug. lipi runs it while the frames are still editable, and points at the component rather than the screen it happened to break on.

context

indic scripts run longer than english and sit taller on the line. a button that fits “save” clips on “सहेजें”. designers rarely see this until it has already shipped.

lipi takes your english frames, generates a hindi or tamil version, re-measures the layout, and flags exactly where the translated text breaks it.

the turn

first direction

the first version only analysed text already sitting on the canvas.

what happened

it found nothing. there is no break to detect until somebody has localized the screen by hand, which is the work you were trying to avoid in the first place.

what changed

the plugin generates the translated screens itself, off to the side, and measures the growth. it has to cause the break before it can point at the cause.

four steps

  1. select

    point it at the english frames you care about.

  2. generate

    a clone is translated into hindi or tamil and re-measured.

    /never writes to your file

  3. preview

    the localized version lays over the original; reveal draws the measurements.

  4. export

    the only permanent write in the whole tool.

key decisions

01

cause the break, don't wait for it

why

the first plan only analysed text already on the canvas, which finds nothing until someone has localized by hand.

tradeoff

the plugin now has to translate and reflow, far past a read-only checker.

result

a clone, translate and re-measure delta engine produces the pressure itself, off to the side, then measures the growth.

02

roll the failures up to their cause

why

forty separate overflow warnings is noise a designer will ignore.

tradeoff

grouping by cause is more work than listing every overflow.

result

issues aggregate into root causes, so you fix the button once and watch the count fall across every screen it appears in.

03

never touch the original

why

a tool that mutates your file to test it is a tool you will not trust.

tradeoff

extra machinery: clones, locked overlays, crash-safe cleanup.

result

preview lays a hidden clone over the original; reveal draws locked overlays and drops you back on the editable layer. export is the only permanent write.

04

hide the engine

why

designers do not need severity scores, confidence values, or the names of internal passes.

tradeoff

all of that sophistication becomes invisible.

result

the interface speaks only in reach and in four plain steps: select, generate, preview, export.

it measures, it does not guess

every flag is geometry: the baseline bounds, the localized bounds, and the growth between them.

outcome

a working prototype, not yet run inside the live figma runtime. hindi and tamil today; the script ranges are written so more indic languages are a small addition, not a rebuild.

reflection

it has not run inside the live figma runtime yet, so the open question is whether the root-cause grouping holds up on a real design file, with its detached instances and its one-off frames. that is the part i would want a designer to break first.
